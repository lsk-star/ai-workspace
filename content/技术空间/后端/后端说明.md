## 这里放什么

- 服务分层与调用方向；
- 领域边界与职责划分；
- 接口契约、错误码与幂等要求；
- 数据归属、迁移与回滚；
- 后端排障结论。

## 不放什么

- 业务源码、SQL 脚本与构建产物；
- 前端页面与交互细节；
- 生产密钥与真实用户数据；
- 未确认的临时方案。

## 建议记录的内容

| 主题 | 说明 |
| --- | --- |
| 分层 | 接入层、BFF、核心域、基础能力 |
| 领域 | 每个域负责什么，不负责什么 |
| 接口 | 路径、错误码、分页、幂等 |
| 数据 | 归属、迁移、回滚 |
| 观测 | 指标、日志、告警 |

## 写作要点

- 跨域调用写清允许与禁止的方向；
- 接口变更写清兼容策略与影响服务；
- 数据变更必须附带回滚方式；
- 排障结论写清触发条件与验证证据。

## Agent 指引

- 修改服务前，先读架构与接口约定；
- 契约变更必须同步前端与测试；
- 不在知识文档中放密钥、账号与真实数据；
- 完成后把新的边界与约束补回本目录。
