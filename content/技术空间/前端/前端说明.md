## 这里放什么

- 前端应用或包的划分与职责；
- 技术栈、构建与发布方式；
- 路由、状态与请求封装约定；
- 与后端接口、设计规范的衔接点；
- 前端特有的排障结论。

## 不放什么

- 完整源码或大段组件实现；
- 后端服务细节 → 「后端」目录；
- 视觉规范原文 → 设计空间；
- 个人开发环境与路径。

## 建议记录的内容

| 主题 | 说明 |
| --- | --- |
| 应用划分 | 有哪些前端应用，各自负责什么 |
| 构建发布 | 命令、产物、环境变量 |
| 状态管理 | 哪些状态放全局，哪些留在组件 |
| 请求与错误 | 接口封装、错误码映射 |
| 约定 | 目录结构、命名、组件复用 |

## 写作要点

- 写「为什么这样组织」，不只列目录；
- 命令与环境变量要能直接复制运行；
- 与后端契约相关的内容链接到接口文档，不重复维护；
- 排障结论写清现象、原因与规避方式。

## Agent 指引

- 修改页面前，先读设计空间与本目录约定；
- 涉及接口时，以技术空间 / 后端契约为准；
- 不把接口地址、账号、密钥写入文档；
- 新主题建子目录存放（如 `请求封装/`），本目录根只留说明；
- 完成后把新的前端约束补回本目录。
