## 目录

```text
content/
├─ 开始阅读/         介绍与快速开始
├─ 产品空间/         需求、验收、产品决策
├─ 设计空间/         原则、交互、组件规范
├─ 技术空间/         架构、接口、技术决策
│  ├─ 前端/          前端工程约定
│  └─ 后端/          后端服务约定
├─ 运维空间/         环境、发布、回滚
├─ 测试空间/         验证、证据、遗留
└─ 空间配置/         空间说明、命名约定、Harness 配置
```

一级目录代表分类，对应左侧导航。分类下可以继续建子文件夹，但不要超过两层。

## 文件命名

- 使用简短、能独立表达主题的名称，例如 `登录与权限.md`；
- 文件名不带日期、版本与作者；
- 一篇文档只讲一个主题，过长时拆分并互相链接；
- 路径即链接，重命名等于改链接，必须全局检查。

## 头部字段

```yaml
---
title: 登录与权限
updated: 2026-11-17
tags: 登录, 权限
summary: 一句话说明本文能回答什么问题
status: 当前维护
---
```

`updated` 是最后确认时间，不是最后保存时间。没有重新确认，就不要更新日期。

## 标签与状态

- 标签用于跨分类检索，每个文档 2–5 个；
- 优先复用已有标签，新标签先确认没有近义词；
- 状态不写进标签，状态用 `status` 字段。

| 状态 | 含义 |
| --- | --- |
| 当前维护 | 可以作为依据 |
| 待评审 | 只能讨论，不作依据 |
| 待验证 | 已有实现，证据不足 |
| 已归档 | 仅作背景参考 |

## 引用

- 站内链接使用相对路径，例如 `[产品空间说明](../产品空间/产品空间说明.md)`；
- 图片放在 `public/media/`，使用 `/media/xxx.png` 引用；
- 外部链接保留原始地址，不转存；
- 引用他人结论时注明状态与日期。

## 归档

过期内容不直接删除，改为 `status: 已归档`，并在文首说明被哪篇替代。

删除会破坏历史链接，也会让后来者失去判断依据。
