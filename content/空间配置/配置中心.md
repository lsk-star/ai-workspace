## 这里放什么

本项目的**代码工程登记表**。数据保存在工作区根目录的 `workspace.json`，本页是它的编辑入口：在表单里逐行增删工程、填写编号、名称、位置与描述，保存后直接写入该文件。

它是可选配置：不填不影响工作区使用；填了以后，AI 只需要以工作区目录为起点，读取 `workspace.json` 就能找到所有工程的位置，不需要在对话里重复说明代码在哪。

## 字段说明

| 字段 | 说明 |
| --- | --- |
| 编号 | 工程唯一标识（如 `web`、`api`），其他资料引用工程一律用编号 |
| 名称 | 项目的可读名称 |
| 位置 | 工程根目录，推荐相对工作区根目录（如 `../book-server`），也可以写本机绝对路径 |
| 描述 | 一句话说明工程职责（可选） |

## 数据格式

`workspace.json` 示例：

```json
{
  "projects": [
    {
      "id": "web",
      "name": "图书前台",
      "location": "../book-admin",
      "description": "用户端站点"
    },
    {
      "id": "api",
      "name": "图书服务",
      "location": "../book-server",
      "description": "接口与任务调度"
    }
  ]
}
```

## 使用约定

- 密钥、账号、令牌不写进 `workspace.json`；
- 工程移动、重命名或废弃后更新登记；废弃的条目保留并注明，不直接删除；
- 未登记的工程，AI 应先向用户确认位置再操作；
- 若仓库公开，注意 `workspace.json` 中的本机位置信息；可以将其加入 `.gitignore`，代价是换机器后 AI 读不到登记。

## Agent 指引

- 任务需要读写业务代码时，先读工作区根目录 `workspace.json` 拿到工程编号与位置，再进入工程；
- 引用工程时使用工程编号，不把工程位置复制到其他文档；
- 新增工程时可以直接编辑该文件补一条登记，也可以提示用户在「空间配置 / 配置中心」的表单里登记；
- 位置变化时只改 `workspace.json`，不动其他资料。
