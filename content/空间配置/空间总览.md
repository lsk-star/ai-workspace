## 当前状态

这是一个**初始化模板**，只包含分类说明与写作指引，不包含具体项目资料。

你为每个项目复制一份工作区，按下面的步骤替换内容。

## 空间构成

| 分类 | 内容 |
| --- | --- |
| 开始阅读 | 介绍、快速开始、目录与命名约定 |
| 产品空间 | 需求、验收、产品决策 |
| 设计空间 | 原则、交互、组件规范 |
| 技术空间 | 架构、接口、技术决策；前端 / 后端子目录 |
| 运维空间 | 环境、发布、回滚、排障 |
| 测试空间 | 验证策略、证据、遗留 |
| 空间配置 | 空间说明、配置中心、Harness 配置 |

分类之外的内容不进入空间。需要新分类时，先确认它不会和已有分类重叠。

## 配置与项目知识分开

| 文件 | 内容 | 编辑方式 |
| --- | --- | --- |
| `AGENTS.md` | 工作区通用规则 | 空间配置 / Harness 配置 |
| `harness/frontend.md` | 个人前端偏好 | 空间配置 / Harness 配置 |
| `harness/backend.md` | 个人后端偏好 | 空间配置 / Harness 配置 |
| `harness/frontend/`、`harness/backend/` | Harness 附属文档（按需读取，可选） | 在仓库中修改 |
| `workspace.json` | 代码工程登记：编号、名称、描述、位置（可选） | 空间配置 / 配置中心 页面表单 |
| `harness/tasks/` | 跨会话任务记录（可选） | 复制 `_template.md` |
| `content/` | 项目知识 | 在仓库中修改 Markdown |

## 初始化清单

1. 修改本页的项目名称、目标与当前状态；
2. 填写「空间配置 / Harness 配置」中的三份配置；
3. 在「空间配置 / 配置中心」登记代码工程（可选，推荐）；
4. 按分类补充真实资料，删除模板说明；
5. 在前端 / 后端项目的 `AGENTS.md` 中接入本工作区；
6. 运行 `pnpm index` 生成检索索引；
7. 第一次任务结束后，检查结论是否真的沉淀到了对应文档。

## 日常维护

```text
任务开始
  → 读取根目录 AGENTS.md
  → 按项目类型读取 harness
  → 需要业务代码时读工作区根目录 workspace.json（配置中心）
  → 用 knowledge-index.json 检索
  → 在业务工程中执行与验证
  → 把结论写回对应分类的模块子目录
  → 更新 updated / status
  → pnpm index
```

- 新结论写入最接近分类的模块子目录，不新增一级分类，不堆在分类根目录；
- 过期内容标记 `status: 已归档`，不直接删除；
- 个人路径、账号与密钥不写入共享资料；
- 目录位置不代表审批结论，引用时同时看状态与日期。
