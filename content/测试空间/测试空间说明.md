## 这里放什么

- 验证策略与检查清单；
- 验收用例与执行结果；
- 可复现的证据（日志、traceId、步骤）；
- 缺陷与遗留问题；
- 未执行或无法执行的检查。

## 不放什么

- 未经验证的产品结论；
- 只写「通过」没有证据的记录；
- 与验证无关的排期讨论；
- 真实用户隐私数据。

## 建议结构

| 主题 | 说明 |
| --- | --- |
| 范围 | 本次验证覆盖什么，不覆盖什么 |
| 环境 | 版本、环境、数据 |
| 用例 | 编号、步骤、预期 |
| 结果 | 通过 / 失败 / 未执行 |
| 遗留 | 现象、规避方式、影响范围 |

## 写作要点

- 每条结论附证据，否则按未验证处理；
- 未执行的检查必须明确写出；
- 缺陷分级依据影响范围，不依据修复难度；
- 发布前确认遗留问题有负责人和时间。

## Agent 指引

- 实现完成后先读验收标准，再设计验证；
- 构建成功不等于业务验收通过；
- 验证结论对应任务与版本，跨版本引用需重新验证；
- 完成后把结果与遗留写回本目录。
