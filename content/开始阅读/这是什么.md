## 一句话

ai-workspace 是你自己的「项目知识空间」：每个项目一份，前端 / 后端代码照常放在各自工程；AI 开始任务前先读这里，就能复用这一个项目的背景。

## 它解决什么

开发一个新项目时，需求澄清、设计取舍、接口约定、排障结论容易散在聊天和笔记里。换一次会话，就要重新解释一遍。

工作区把这些内容按分类保存成 Markdown，人和 AI 读同一份文件。已经确认的规则不必反复解释，已经验证的路径可以继续参考，没解决的问题也不会随着会话结束而消失。

## 它不是什么

- **不是代码仓库**：前端、后端源码仍在各自工程；
- **不是团队协作平台**：没有账号、权限、多人实时编辑；
- **不会自动记住一切**：AI 能不能复用上下文，取决于资料有没有被维护和读取。

## 怎么配合 AI

```text
你在项目 AGENTS.md 里指向工作区
  → AI 读工作区 AGENTS.md
  → 按项目类型读 harness/frontend.md 或 backend.md
  → 检索项目知识
  → 在工程中实现与验证
  → 把结论写回工作区
```

## 三份配置

| 文件 | 作用 |
| --- | --- |
| `AGENTS.md` | 通用检索、沉淀、禁止项 |
| `harness/frontend.md` | 前端技术栈、目录、代码风格、测试 |
| `harness/backend.md` | 后端分层、错误处理、数据、测试 |

## 第一次进来先读什么

先读左侧「开始阅读 / 快速开始」，它会带你一步步把项目接进来：创建工程 → 写「项目知识空间」接入段 → 填 Harness → 开始第一次任务。全程照着点就行。

## 目录

| 分类 | 放什么 |
| --- | --- |
| 开始阅读 | 介绍、快速开始、目录与命名约定 |
| 产品空间 | 需求、验收、产品决策 |
| 设计空间 | 交互、状态、视觉规范 |
| 技术空间 | 架构、接口、技术决策；前端 / 后端约定 |
| 运维空间 | 环境、发布、回滚、排障 |
| 测试空间 | 验证策略、证据与遗留 |
| 空间配置 | 空间说明、配置中心、Harness 配置 |

## AI 如何高效检索

1. 先读 `knowledge-index.json`，用标题、标签、摘要定位文档；
2. 再在 `content/` 下按关键词搜索；
3. 只精读命中的文档；
4. 新增内容后运行 `pnpm index` 更新索引。
