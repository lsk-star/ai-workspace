# Harness

个人规则目录，与项目知识分开存放。规则文件按主题拆分，AI 按任务类型读取对应文件。

| 文件 | 用途 | 何时读取 |
| --- | --- | --- |
| `AGENTS.md`（根目录） | 工作区规则 | 每个任务 |
| `frontend.md` | 前端技术栈、目录、风格、测试 | 前端工程任务 |
| `backend.md` | 后端分层、错误处理、数据、测试 | 后端工程任务 |
| `design.md` | 设计取舍、交互与视觉约定 | 设计类任务（存在时） |
| `<名称>.md` | 自建规则 | 按任务需要 |
| `rules.json` | 规则显示名登记 | 供页面下拉与清单接口读取 |
| `frontend/`、`backend/` 等附属目录 | 附属文档（可选） | 主文件清单引用时按需读取 |
| `tasks/` | 跨会话任务计划与交接（可选） | 多步骤或中断后继续的任务 |

## 大小上限

- 每份 harness 规则主文件（`frontend.md`、`backend.md` 等 `harness/*.md`）不超过 2500 字符：每次会话都要读，必须保持精简；
- 根目录 `AGENTS.md` 不设硬上限，但每一条都必须值得每次会话支付；能放 `content/` 的知识不进规则文件；
- 接近上限时，把稳定的细节拆到对应附属目录下按主题命名的附属文档；
- 主文件只留「附属文档清单」：一行一条，写路径和一句话说明；
- 页面「空间配置 / Harness 配置」保存时超过上限会被拒绝，先拆分再保存。

## 怎么改

- 在页面「空间配置 / Harness 配置」下拉选择规则，预览或编辑，保存直接写入文件；
- 下拉里「新建规则」可以沉淀新主题，保存时自动创建 `harness/规则名.md`；
- 显示名登记在 `rules.json`，未登记的规则用文件名显示；
- 规则只写个人偏好与通用规则，不写项目业务内容；
- 不写账号、密钥和个人绝对路径。

## 任务记录

`tasks/` 只用于跨会话、跨模块或需要交接的任务。日常小改动不需要新建任务文件。

- 使用 `tasks/_template.md` 复制；
- 文件名用日期与主题，例如 `2026-11-17-登录模块.md`；
- 完成后标记状态，遗留事项写清楚；
- 不把聊天全文、一次性命令写进任务记录。
